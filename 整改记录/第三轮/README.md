## 三、安全边界（已实测）

| 边界 | 实现方式 | 验证 |
|---|---|---|
| 凭据不下发浏览器 | 只在网关进程内存中；网页只能调 5 个只读接口 | `G-secret` / `P-4` |
| 只监听本机 | `server.listen(port,'127.0.0.1')` | `G-host` 非本机 Host → 403 |
| 拒绝跨域 | 只放行 `127.0.0.1` / `localhost` 来源 | `G-origin` → 403 |
| 写操作不可达 | 只读白名单 12 个工具；下单/领券/积分/地址路径不存在 | `G-*api*` 6 项 → 404 |
| 组合爆炸防护 | 单次算价最多 20 个商品 | `G-limit` |
| 个人隐私不出网 | 隐去 `fullAddress`/`addressId`/`contactName`/`phone`/`traceId` | `G-priv` |
| 门店公开地址保留 | 门店地址是选店必要信息，**不**隐去 | `C-3` / `E-03` |

**没有做**：下单、领券、积分兑换、新增地址。架构上不可调用，也不只是"暂不测试"。

## 四、真实模式的用户流程

```
首页 → 确认门店（城市+关键词）→ 就餐方式 → 适用时段
     → 加载该门店真实可售菜单（显示来源/更新时间/可售数量）
     → 八道独立问题（人数·预算·已有食物·口味·二选一·尝新·多餐·记忆同意）
     → 真实推荐（商品编码来自该门店菜单）
     → 改数量 / 换单品 / 改规格
     → 官方算价（商品金额·优惠·费用·总额）
     → 保存或复制餐单
```

### 关键设计

- **候选生成在本地**：按角色（主食/小食/饮品）分组，本地枚举组合并**在预算内筛选**，只对最终选中的 1 个方案调用官方算价——不做组合爆炸，也不逐项轮询。
- **报价绑定签名**：报价记录 `ctxVersion + 商品编码 + 数量 + 规格`。人数、商品、规格、门店任一变化，签名不再匹配，界面立即把旧价标为**已过期**并要求重算（保留旧价供对照，不静默替换）。
- **过期响应不会覆盖新选择**：算价请求携带 `ctxVersion`，网关发现上下文已变更直接返回 409。
- **未知就是未知**：营养与过敏原官方接口未返回，界面标注「未知」，**不从商品名称推断**，更不会把未知过敏原当作安全。
- **失败不伪装**：网关不通、菜单失败、算价失败都显式报错并给出重试/切换入口，**绝不回退到演示数据**。

## 七、本轮修掉的真实缺陷

这些都是跑通过程中**实际暴露**的，不是预防性猜测：

| 现象 | 根因 | 影响 |
|---|---|---|
| 改数量后系统悄悄换成另一套商品 | 每次渲染都重跑搜索，总价变化改变了排序 | 用户以为在改 A，实际会买 B |
| 报价永远显示「已过期」 | 菜单响应覆盖了 `S.ctx`，丢掉 `ctxVersion` | 用户无法确认当前价格是否有效 |
| 数量改了又弹回原值 | 修改写在临时对象上，未持久化 | 功能形同虚设 |
| 第 8 题走不下去 | 记忆同意是逐项开关，缺少继续入口 | 流程死锁 |
| 门店列表几家无法区分 | 脱敏规则按 `/address/` 匹配，把门店公开地址也隐去 | 无法选店 |
| 规格弹层点不动 | `<form method=dialog>` 提交抢先关闭弹层 | 无法选规格 |
| 确认按钮永远禁用 | 元素缺 `id`，`$('#confirm-store')` 取到 null | 无法确认门店 |
| 搜店永远 0 结果 | 前端发 `{city, kw}`，网关要 `{city, keyword}` | 无法进入真实模式 |
| 跨域被拦 | 网关与网页不同端口，未放行本机 CORS | 真实模式完全不可用 |
| `[object HTMLSpanElement]` 显示在报价上 | `el(t,c,x)` 的第三参是文本，误传元素 | 界面出现乱码 |
| 改坏产物仍报「零漂移」 | 构建器按外层布局拼路径，独立包里目标缺失被跳过 | **交付可信度问题**（第三版 R3-02） |
